# Security

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/otaviobarros/agent-engineering/security/advisories/new).
Sign in to GitHub and submit a report to this repository's maintainers.
Private vulnerability reporting is enabled for this repository.

Include the affected plugin version, agent host and version, expected behavior,
observed behavior, impact, and minimal reproduction steps. Use a disposable
example and redact credentials, personal information, and private project data.
Never include a working secret or exploit a repository you do not control.

Keep vulnerability details out of public issues. The maintainers will assess
reports, investigate reproducible problems, and coordinate fixes and disclosure
through the private advisory. No response deadline or bounty is promised.
GitHub controls access to and storage of advisory records under its
[privacy statement](https://docs.github.com/en/site-policy/privacy-policies/github-privacy-statement).

## Scope

Reports may concern shipped skills, shared references, manifests, assets, or
instructions that could cause unintended access, disclosure, or operations.
Include the affected release tag. Reproduce on the latest release when practical;
older releases are immutable and fixes ship in a new version.

The plugin guides the agent; host permissions and execution remain with the host.
For defects in the host or another service, use that provider's security channel.
For ordinary support, use [GitHub Issues](https://github.com/otaviobarros/agent-engineering/issues).
